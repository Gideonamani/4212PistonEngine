# GTSIO-520-H internal accessory-drive extension

This study extends the accepted `drive-development` engine with a compound idler, two magneto drives, the selected H replacement fuel drive, pressure/scavenge pumps, and the external starter drive inside a simplified stationary shell. It adds 69 parts, including ten gear/shaftgear components. Static construction precedes engine animation.

- `research.md` separates source anchors, deductions and estimates.
- `inventory.json` records all reviewed component dispositions; `research-readiness.json` checks coverage, not manufacturer fidelity.
- `part-spec.json` is generated by `cad_pipeline/gtsio_static_accessories.py`. Shared spur geometry and relationships come from `scripts/accessory_gears.py`.
- `iteration-learning.md`, `first-attempt-failures.json` and `second-attempt-interference.json` retain diagnosed failures.
- `bevel-method.md` and its check report retain the successful isolated governor-ratio method fixture.
- `remaining-drives.md` lists unfinished branches and their modelling dependencies.
- `rear-diagram-plan.json`, `internal-diagram-plan.json` and `presentation.json` hold recorded cameras and selected actual part IDs. They do not certify image registration or resemblance.

R3 at `build/gtsio520-accessories-r3/` passed 1,279 direct-solid, 4,726 mesh-pair and 25 interface checks, but was superseded after source review corrected the magneto adapter orientation and bush length. Its native build was stopped before acceptance. R4 at `build/gtsio520-accessories-r4/` carries the correction and requires fresh affected-geometry and full assembly checks. Native extension and final presentation remain separate acceptance stages; consult their actual reports before treating a package as accepted.

## Rebuild and validation route

Generate the source specification with `python -m cad_pipeline.gtsio_static_accessories`. For a new parameter set, `adopt_direct_cache.py` can carry eligible parts from the verified native base. Within an unchanged parameter set, `reuse_direct_snapshot.py` seeds a fresh development folder with exact cache hits from a prior trial, including individually valid parts of a failed assembly. It never inherits that assembly's acceptance.

Run `fast_build.py --jobs 1`, then `audit_gtsio_accessory_interfaces.py` on its BREP cache. Convert and audit the actual development GLB under the unchanged engine interference policy. Resolve every failed solid, interface and overlapping pair before the native build.

Use `extend_saved_native.py` against `build/gtsio520-drive-r4/cad`, with batching6 and checkpoints every20 rebuilt parts. Resume interrupted construction with `--resume` only against the same source/specification. A checkpoint is not a complete CAD package. Follow completion with `verify.py`, the interface audit against the saved package, and `audit_gtsio_static.py` using the direct BREP cache plus the accepted base's `static-pair-cache.json`. Retain new pair checkpoints for safe resumption.

Render/export through `present.py`; reopen/verify with `verify_blender.py`; audit that final GLB. Render the comparison plans from the saved native geometry and inspect them against the OEM figures. Record resemblance separately from geometry acceptance. Keep CAD/STEP/Blender/GLB/PNG binaries locally under ignored `build/`; no student release or upload is part of this phase.

Tests: `scripts/test_gtsio_accessories.py` checks ratios, backlash, sampled full-pitch meshes, deliberately incorrect phases and pressure-depth derivation. `scripts/test_reuse_direct_snapshot.py` checks conservative cache invalidation and preservation of source records. Run CAD-dependent scripts with the installed FreeCAD Python.

R4 development checks passed: 1,279 valid solids (1,206 adopted unchanged), 31 actual interface measurements, and 4,716 exported neighbouring pairs with zero detected overlaps and no unverified meshes. Three rendered comparison views were inspected; `development-comparison.json` records remaining mismatches. `build/gtsio520-accessories-r4/development-review.html` is explicitly a development review. Saved-native validation remains pending.

## Native checkpoint recovery and queued gates

All 1,279 native parts were built and checkpointed. Final packaging detected a reused-history volume drift in RodBoltB5: 3549.8451303630677mm3 versus the accepted 3549.841138679717mm3, with matching bounds. Explicit reconstruction from the unchanged recipe restored 3549.841138679717mm3. The original failure is retained in `native-reuse-failure.json`; no tolerance was relaxed. This recovery alone is not final saved-package acceptance.

`validate_accessory_package.py` runs a finite sequential gate job, optionally waiting for completed native export: reopen/STEP, saved interfaces, then exact native intersections with previous-pair reuse. Current progress is in `build/gtsio520-accessories-r4/validation-workflow.json`; stage logs and the pair checkpoint are under its `cad/` directory. A failure stops later gates. Check actual reports before starting presentation or claiming acceptance. Do not launch a duplicate validation job while one is active.

`drive-paths.md` supports the accessory-drive lesson. `governor-fit-planning.json` records calculated source-based journal fits for the next branch; it does not represent installed geometry.
