# Methods for the static drive reconstruction

FreeCAD 1.1.1 remains the geometry master. Reuse the tested primitive/Boolean, ruled-loft, helix, matching-seat and checkpoint methods from the crankshaft, cylinder and valve-train milestones. Reopen a method when the actual new topology contradicts its fixture; prior acceptance does not waive the new assembly checks.

## Editable calculated gear outlines

Question: how can calculated involute outlines retain useful native editing without hundreds of sketch constraints? A direct `Part::Feature` prism is fast but freezes the profile; a constrained sketch is expensive for a many-point gear. The chosen opt-in `linked_profile` instead uses an expression-driven `Part::Polygon` and a linked native `Part::Extrusion`. Whole Nodes-list expressions follow the already-tested loft pattern. Custom extrusion direction follows the profile's complete axis/roll transformation.

Primary source inspected: [FreeCAD 1.1.1 FeatureExtrusion.cpp](https://github.com/FreeCAD/FreeCAD/blob/1.1.1/src/Mod/Part/App/FeatureExtrusion.cpp), constructor properties Base/DirMode/LengthFwd/Solid and execution's transformed-base face/extrusion path. The initially guessed FeaturePartExtrude.cpp URL was inaccessible; it was not studied. The actual versioned source was found and inspected. Existing installed native APIs are exercised by the fixture; no new workbench or kernel is introduced.

`test_linked_profile.py` saves/reopens an involute outline with an off-axis placement and roll, changes module, face width and bore, then saves/reopens and exports again. Both tests pass. Native/direct volume error is at most 3.97e-16 and bounds error 2.85e-14 mm; strict STEP passes. `profile-method-checks.json` records this isolated result. It establishes the method, not OEM tooth form, counts or full assembly operation. Tooth count/topology and solved phase still require regeneration; scalar profile/width/bore edits are native.

The standard-library `gear_geometry.py` supplies conjugate sampled involute flanks and solved phase. Source fits supply pair backlash; tooth counts, module, 20-degree pressure angle and standard addendum/dedendum remain declared estimates. Check complete tooth-pitch clearance and actual saved/exported shapes, rather than inferring safe engagement from a render.

## Durable reuse and independent checking

Native module edits scale the sampled outline, including its original backlash allowance. If a source-fixed physical backlash must remain constant while module changes, regenerate the shared gear solution and profile rather than assuming the linked outline solves that new engineering requirement. The fixture establishes editable geometry and export survival; it does not certify every edited assembly fit.

Extend the hash-verified R5 native package with `extend_saved_native.py`; preserve its files and use separate incomplete checkpoints. The direct evaluator also has caches that belong to identical earlier recipes. `adopt_direct_cache.py` verifies the base saved/direct acceptance and specification, classifies controlling-parameter and shared-master dependencies, then carries only eligible direct JSON/BREP records into the new cache namespace. It never substitutes native shapes for direct ones. Changed parts are freshly evaluated; every final part still receives independent saved/native/direct checking. Missing or mismatched caches rebuild normally.

R2 spaces the rows 24 mm apart, derives full-width flat lands and bores, and uses a 1.0 mm pin inside the washer thickness. The lesson is to constrain the whole nut/washer/pin envelope, not merely the shaft centre line.

## Reusing expensive exact pairs

Installed FreeCAD 1.1.1 / OCCT 7.8.1 API documentation was inspected for `exportBrepToString`, `copy(copyGeom=True, copyMesh=False)` and `cleaned`. A native probe confirmed that tessellation changes BREP serialization; cleaning a copy removes triangles but may retain changed kernel topology flags. The chosen fingerprint therefore retains those flags and full precision, accepting safe misses. It never changes the original solid used by `common`. This implementation evidence establishes a cache method, not engine dimensions.

`static_pair_cache.py` binds each pair to both copied-boundary and assembled-placement hashes, ordered identities, original intersection policy, installed software identity and source-file hashes. It enumerates every current neighbour. Partial checkpoints retain completed pairs atomically; incomplete work cannot become a full pass. A legacy pass may be indexed only against its original complete saved native/specification and unchanged neighbour count, preserving “below threshold” rather than inventing zero volumes. The native mutation fixture and actual engine warm-reuse results are retained separately. See `docs/static-audit-reuse.md`; unchanged camera/lighting edits preserve geometry/export audit evidence, while actual CAD/export/motion changes invalidate the relevant checks.

The initial legacy index assumed specification order matched saved object order. A direct read of the native `doc.Objects` list disproved that assumption. The corrected index and future auditor preserve saved document order, including the numerical `common(a,b)` operand direction. The current correction reorders only unknown/below-threshold outcomes from the original exhaustive pass; it never reverses an actual measured volume. Previously verified geometry fingerprints are unchanged. The original attempt, actual saved ordering and correction hashes are preserved; the final engine warm check uses the corrected cache. Treat ordered pair direction as part of numerical-method provenance.
